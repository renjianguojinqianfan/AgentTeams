## 4. 质检 rubric（重写 prompt）

| 维度 | 权重 | 标准 |
|---|---|---|
| 准确性 | 40% | 产品/政策/流程与知识基线一致，无编造 |
| 完整性 | 20% | 覆盖客户核心诉求 |
| 合规安全 | 15% | 无隐私泄露、违规承诺、绕过审批 |
| 服务态度 | 15% | 专业、共情、有引导 |
| 效率 | 10% | 直奔主题、及时转人工 |

评分 0-100 五档（优秀/良好/及格/不及格/较差）；无效回答 0 分；禁止编造；知识基线缺失→feedback 声明缺失证据。

## 5. 缺失证据段（准则 3）

`EvaluationReport.missing_evidence: list[str]` 由 `service.aggregate_missing_evidence` 确定性聚合：
- 批次 LLM 失败（degraded_reasons）→ 该批未逐题验证
- 单题置信度 `low`（needs_review）→ 评分自信不足，需人工复核
- 坐席未应答（user_answer 空）→ 无应答可评

去重保序。输出 CLI 显式打印「缺失证据段」。

## 6. 降级策略（LLM-as-Judge 鲁棒性）

两级降级沿用源：
1. 批次评估失败 → 逐题补零 + 缺失证据段透出失败原因
2. 二次汇总失败 → 降级到批次聚合结果

新增：单题 `confidence=low` → 保留分数但标记 `needs_review`（只标注不评分语义，报告暴露需人工复核计数）。overallScore 容许 float 并取整，避免 LLM 输出小数导致整批误降级（e2e 实测 54.3 触发，已修）。
