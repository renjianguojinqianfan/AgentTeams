# P5 彩排剧本（智服 · 双闭环演示）

> 前置：AgentTeams 集群运行中（`setup.sh` 建队）、LLM env 注入（qwen3.7-flash 或 3.7-plus）。
> 验收目标：**全程无人工救场**（每个角色动作自然触发，无需演示者代答/代操作）。
> 主证据：`tmp/closedloop-verify/2026-08-13-closedloop.json`（进化达标）+ `tmp/full50-verify/`（B5 全量对照，若成功）。

## 角色

| 角色 | 在演示中扮演 |
|---|---|
| 演示者（人类） | 客户（发咨询）、协调人（必要时触发进化） |
| servevo-leader | 分诊派单、触发进化、汇报指标 |
| servevo-cs | 客服主岗：RAG 应答、高危操作发起审批 |
| servevo-qc | 质检·审批官：抽检评分、审批高危/知识变更 |
| servevo-coach | 陪练官：陪练剧本、知识修订草案、回归测试 |

## 场景一 · 服务闭环（保可信）

**一句话启动**：向 servevo 房间发：「客户咨询 K2 咖啡机价格和保修期，请处理。」

| 步骤 | 触发 | 预期输出（无救场判定） |
|---|---|---|
| 1 | 客户提问 | Leader 分诊 → 派给 servevo-cs |
| 2 | cs 应答 | 检索知识库，回复「K2 价格 ¥3299 / 整机保修 1 年」（带来源） |
| 3 | 高危操作（演示加戏：「客户要求退款 300 元」） | cs 发起审批 → servevo-qc 审批 → 执行/拒绝并回复客户 |

**救场信号**：cs 答不出价格/保修（知识检索失败）或高危操作未触发审批 → 本轮不过。

## 场景二 · 进化闭环（保进化）

**触发**：客户问 2026 新政策（v1 未收录，如「整机保修期延长到多久？」）。

| 步骤 | 触发 | 预期输出 |
|---|---|---|
| 1 | 客户提问 | cs 应答「v1 知识无新政策，转人工核实」 |
| 2 | qc 抽检 | 按 rubric 评分（缺口题低分）→ 产出薄弱点 |
| 3 | Leader 触发进化 | 派 coach 生成陪练剧本 + 知识修订草案 |
| 4 | qc 审批 | 审批知识修订 → Registry 发布 v2（stable=canary 切换） |
| 5 | 回归复测 | 同测试集复跑 → v1/v2 指标对比 |
| 6 | Leader 汇报 | 汇报：解决率↑ / 转人工↓ / 质检分↑ / 回归通过率 |

**救场信号**：修订草案无内容、审批未触发、v2 未发布 → 本轮不过。

## 场景三 · 量化对照（数据证据）

现场展示（非现场跑，防翻车）：
1. `closedloop-verify/2026-08-13-closedloop.json`：v1→v2 进化达标曲线（解决率 0.67→1.0 / 转人工 0.33→0 / 质检分 91→95 / 回归通过率 0.67→1.0）
2. `full50-verify/2026-08-13-full50.json`（B5）：50 题全量 v1/v2 对照（v1→v2：解决率 0.88→0.92 / 转人工 0.12→0.08 / 质检代理分 84→86 / 回归通过率 0.76→0.84）
3. 解释口径：指标全部由**真实应答推导**、v2 知识包真实物化（5 缺口全解）、diff 可审计、缺失证据段如实声明；全量 50 题回归通过率 0.84 未达 0.95 属真实局限（检索/应答完整性），逐题在 cases_v1/v2 可对质

**救场信号**：评审追问「指标怎么来的」答不上 → 用快照逐项对质（ts/answers/signals）；追问「为什么没到 0.95」→ 指出真实局限 + 逐题证据，不回避。
