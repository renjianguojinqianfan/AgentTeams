单 Worker（servevo-cs 原型）能对 Matrix 消息执行**基于知识的应答**：`task→answer` 成功，回答引用 `product-knowledge` references，遇未知明确转人工（无幻觉），可选带检索轨迹（retrieval_trace）。

## 4. 检索实现（替换 pgvector）

`search_knowledge_base_impl` 新语义（依赖文件系，无 DB）：

```
输入: question, kb_dir(=references/), top_k
步骤:
 1. 读 references/*.md → 按 ## 标题切分块（每块带 source 文件名+行号）
 2. 中文分词简化（2-gram + 关键停用词过滤）+ 英文小写 token
 3. BM25 简化计分：tf * idf（idf 用块数/文档数），标题词加权 ×1.5
 4. 正则兜底：产品型号（K1/K2）、词表路由（保修/退换/价格/故障→对应文件加权）
 5. 返回 top_k：{content, score∈[0,1], source, section}
```

阈值沿用：`_MIN_CHUNKS_THRESHOLD=2`、`_MIN_SCORE_THRESHOLD=0.5`、`_MAX_RETRIES=2`（信任原图）。

**为什么“keyword 检索而非向量”**：红线禁pgvector；50 题知识总量=3 references（~2.5KB），BM25 足够且零依赖；评分语义=可解释（答辩卖点：无幻觉可审计、无重依赖）。

## 5. LLM 通道（Higress）

- `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 环境变量（manager 侧注入，容器内不落盘）
- `get_chat_client()` 返回 langchain OpenAI-compatible client（httpx/OpenAI SDK），失败→图内降级：`answer` 明确“无法连接模型”，不静默
- 复用 qwen3.7-flash（worker 档）跑 cost 敏感路径；答辩口径与踩坑手册一致
