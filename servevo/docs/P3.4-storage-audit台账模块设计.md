# P3.4 storage/audit/台账模块设计

> 状态：Draft（2026-08-09）→ 验收口径：产物+审计+指标 jsonl 落存储（规划 §P3.4）
> 决策依据：规划 §4.4 可观测三类数据（Log=MinIO 归档 / Metrics=指标 jsonl）；AGENTS.md「双基座叙事」

## 1. 目标

为进化闭环提供**审计与指标底座**：
- 产物归档（transcripts/质检报告/陪练报告）落存储
- 审计链（关键动作 append 式 jsonl）
- 指标台账（v1/v2 量化对照的 jsonl 时序）

支撑 P4.4 量化对照（解决率↑/转人工率↓/质检分↑/回归通过率）与 P4.3 可回滚（版本 diff 审计）。

## 2. 双后端存储（自建等价物同契约）

| 后端 | 触发 | 用途 |
|---|---|---|
| LocalStorage | 默认（`SERVEVO_STORAGE_DIR`） | host 侧可验证，零外依赖 |
| MinioStorage | `S3_ENDPOINT` 非空 | 生产（MinIO 容器内 127.0.0.1:9000） |

MinIO 不在 host 暴露（容器内可达），故 host 验证用本地后端——**同契约等价物**（AGENTS.md 红线：无云资源时自建等价物同契约）。

## 4. 指标台账（v1/v2 量化对照核心）

`resolution_metrics(solved, escalated, total, qc_avg_score, regression_pass, regression_total)` 确定性聚合：
- resolution_rate = solved/total
- escalation_rate = escalated/total
- qc_avg_score = 质检平均分
- regression_pass_rate = regression_pass/regression_total

`MetricsLedger.append(version, metrics)` 落 `ledger/<version>.jsonl`，追加式时序。v1/v2 对比即按 version 读取两文件。

1. 单测 8/8：存储 roundtrip / 路径穿越防护 / key 安全 / 指标聚合 / 台账追加 / 审计 hash

## 6. 风险

| 风险 | 缓解 |
|---|---|
| MinIO host 不可达 | 本地后端等价物同契约；MinIO creds 已 mc 实测 |
| 审计 append 读改写并发 | 单写者场景（进化闭环串行）；如需并发可换对象版本号 |
| 指标口径漂移 | resolution_metrics 单一确定性函数，v1/v2 同源 |
